# Trading journal — Feb 2023 to Sep 2024

The trading journal from my personal account: discretionary macro, trading
CFDs on currencies, indices, gold and oil. I traded alongside other work from
February 2023 and full time from September 2023 to September 2024. I haven't
traded since September 2024 and have no capital invested.

**The account finished at breakeven.** This journal is not the account's full
history and it is not a performance record. It's a documented sample: 54
positions over 20 months (29 winners, 24 losers, 1 breakeven), the trades
whose reasoning I could explain properly. The trades that never made it into
the journal were mostly losers.

Each month is a set of first-person entries: the macro and technical reasoning
behind a trade, how it was sized and managed, and the outcome or lesson. I
wrote the journal as I went and cleaned it up in 2026.

## The system

- Scenarios built over several days before I put anything on.
- A reward-to-risk of at least 1.5 on every entry.
- Size cut by 25% after three losses in a row.
- Out as soon as the scenario is invalidated.

The entries show where I kept to these rules and where I didn't.

## Reading the numbers

Results are in R, the multiple of the risk taken on that trade. They describe
the logged trades only: a month's R doesn't match that month's statement, and
the journal's total isn't the account's result. Positions whose exit I never
wrote up, or whose R I didn't record, have no figure and aren't counted.

Across the 20 months, the 54 logged positions add up to **+40.46R**.

Months are plain markdown (`track_record/YYYY-MM.md`); with only 2-4 trades
a month, a notebook doesn't add anything over well-formatted text. The months
roll up into **year-in-review** notebooks (`track_record/years/`) and one
**full-history** notebook (`track_record/global_track_record.ipynb`), which
chart R by month and cumulative R across the sample.

## Repo layout

```
data/YYYY-MM.py                        Source content for each month (kept locally,
                                        not published — see .gitignore). This is
                                        what track_record/ is generated from.
data/price_cache/{TICKER}.json         Cached daily OHLC (kept locally, not
                                        published) used to draw the per-trade
                                        and context charts below.
data/ff_calendar/YYYY-MM-DD.json       Cached Forex Factory economic-calendar
                                        rows for one day (kept locally, not
                                        published) used to draw the calendar
                                        tables below.
track_record/YYYY-MM.md                Each month's entries, plain markdown.
track_record/charts/YYYY-MM/*.png      Per-trade price charts, secondary-asset
                                        context charts, and economic-calendar
                                        tables embedded in the month files
                                        above.
track_record/years/YYYY.ipynb          Year-in-review rollup notebook.
track_record/global_track_record.ipynb Full-history rollup notebook.
src/journal.py                         Shared helpers: stats, chart styling,
                                        per-trade chart rendering.
src/build_notebooks.py                 Generates track_record/ from data/*.py.
```

The two rollup notebooks are **self-contained**: each month's figures are
embedded directly in the notebook itself, so nothing outside the notebook is
needed to read it or re-run it. `data/` is only used to *build* everything —
it isn't part of what's published here.

## Charts

The year and full-history notebooks each plot R by month and a cumulative-R
curve.

Every trade with an exact entry date also gets its own price chart, embedded
directly in that month's markdown file. Each one shows daily price action for
roughly a month around the entry: a coloured bar per day for that day's
high/low range (green if the close rose from the previous close, red if it
fell), the daily close connected as a line on top, and a dashed vertical line
marking the entry date. Data is daily OHLC pulled from Yahoo Finance and
cached locally as `data/price_cache/*.json`; charts are generated by
`journal.render_trade_chart()` and regenerated automatically by
`build_notebooks.py` whenever a month is rebuilt. Trades logged with only a
coarse month (no exact day) don't get a chart, since there's no single date
to center one on.

A handful of trades were explicitly reasoned off a second asset rather than
just the traded pair itself — oil driving a CAD view, DXY or the 10-year
yield driving a dollar view, the S&P or VIX behind a broader risk-on/risk-off
read. Those entries carry a `context` field naming the asset(s), and get an
extra chart for each one, in the same style, appearing inline under the
trade's write-up. Entries without a `context` field (most of them) don't get
one — this is only added where the trade's own reasoning names a specific
driver.

Every dated trade also gets a small economic-calendar table for that day,
scraped ahead of time from Forex Factory and cached locally as
`data/ff_calendar/YYYY-MM-DD.json`, filtered down to the currencies the
traded pair actually involves and showing each event's actual, forecast and
previous reading with a coloured dot for its impact level. Some trading days
simply had no relevant release for that pair's currencies, in which case no
table is shown — that's expected, not a bug.

Context charts are generated by `journal.render_context_chart()` and
calendar tables by `journal.render_trade_calendar()` /
`journal.render_calendar_table()`, both regenerated automatically alongside
the per-trade price chart whenever a month is rebuilt.

## Using this repo

```bash
pip install -r requirements.txt
jupyter lab track_record/global_track_record.ipynb   # full history
# or open a single year, e.g. track_record/years/2024.ipynb
# months are just markdown — read track_record/2024-07.md directly
```

The two rollup notebooks are pre-executed, so their charts render statically
on GitHub without needing to run anything. To regenerate after editing
`data/`:

```bash
python3 src/build_notebooks.py --execute        # rebuild + run everything
python3 src/build_notebooks.py --only 2024-08   # just one month's markdown
```
